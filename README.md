Это проект для получения случайного мода с сайта [nexusmods](https://www.nexusmods.com/)

## Начало работы

Проект использует Bun 1.4.2 или новее для установки зависимостей и запуска Next.js.

Установите зависимости из зафиксированного lock-файла:

```bash
bun install --frozen-lockfile
```

Скопируйте `.env.example` в `.env` и заполните `NEXUSMODS_KEY` вашим ключом Nexusmods API. `.env` исключён из Git и Docker-контекста:

```powershell
Copy-Item .env.example .env
```

Затем запустите dev-сервер:

```bash
bun run dev
```

Откройте [http://localhost:3000](http://localhost:3000) с помощью браузера, чтобы увидеть результат.

## Проверка и production-запуск

```bash
bun run typecheck
bun run lint
bun run test
bun run build
bun run start
```

Production-сервер запускается на [http://localhost:3000](http://localhost:3000). Команды `dev`, `build` и `start` выполняют Next.js под Bun.

Для запуска готовой сборки на другом порту:

```bash
bun --bun next start -p 3006
```

Перед обновлением зависимостей или повторной сборкой остановите работающий production-сервер: ему нужны прежние `node_modules` и `.next`. После перехода с npm выполните `bun install --frozen-lockfile`, затем `bun run build` и `bun run start`.

Используются совместимые ESLint 9 и TypeScript 6. Тесты Vitest выполняются через `bun run test` и используют Node.js (версия указана в `engines` в `package.json`).

Поиск ограничен 30 попытками и 20 секундами. Ошибки доступа, лимит запросов и сбои Nexusmods останавливают поиск с понятным сообщением. Переключение игры или фильтра взрослого контента отменяет текущий поиск. Список игр кэшируется на сутки после сокращения данных до названия, домена игры и числа модов.

## Переменные окружения

Шаблон всех настроек — `.env.example`. Ключ нужен только при запуске приложения: сборка не обращается к Nexusmods. Список игр загружается при первом запросе страницы, затем кэшируется на сутки.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `NEXUSMODS_KEY` | Ключ Nexusmods API; обязательный для загрузки игр и поиска модов | Не задан |
| `LOG_LEVEL` | Уровень серверных JSON-логов: `debug`, `info`, `warn`, `error` | `info` |
| `HISTORY_DB_PATH` | Путь к файлу SQLite; каталог должен быть доступен для записи | `data/roll-history.sqlite` |

## Docker

Сборка из корня проекта:

```bash
docker build -t kover-roller:local .
```

Dockerfile использует Bun 1.4.2: отдельные этапы устанавливают зависимости по `bun.lock` и собирают Next.js в [режиме standalone](https://nextjs.org/docs/app/api-reference/config/next-config-js/output). Финальный образ основан на `oven/bun:1.4.2-slim` и содержит только автоматически отобранные серверные зависимости, `.next/static` и `public`. Полный `node_modules` и кэш сборки в него не копируются. Сервер запускается командой `bun server.js` от пользователя `bun`, слушает `0.0.0.0:3000`; SQLite и рабочий кэш доступны для записи.

Standalone включается переменной `BUILD_STANDALONE=1` только на этапе Docker-сборки. Обычные локальные `bun run build` и `bun run start` продолжают работать как раньше. `.dockerignore` исключает локальные секреты, базы, логи, зависимости и результаты предыдущих сборок. Для установки пакетов и загрузки шрифта Rubik при сборке нужен доступ в интернет.

Размер проверенного образа `linux/amd64` после перехода на standalone и Bun slim — 367 МБ вместо 1,26 ГБ по выводу `docker image ls`. Размер своей сборки можно посмотреть командой `docker image ls kover-roller:local`.

После создания `.env` с ключом запустите контейнер:

```bash
docker run -d --name kover-roller --restart unless-stopped --env-file .env -e HISTORY_DB_PATH=/app/data/roll-history.sqlite -p 3000:3000 -v kover-roller-data:/app/data kover-roller:local
```

Откройте [http://localhost:3000](http://localhost:3000). Если этот порт занят dev-сервером, замените `-p 3000:3000` на `-p 3006:3000` и откройте [http://localhost:3006](http://localhost:3006). Переменная `HISTORY_DB_PATH` явно переопределяется после `--env-file`, чтобы локальный путь из `.env` не изменил каталог хранения в контейнере.

Volume `kover-roller-data` сохраняет SQLite, включая сопутствующие файлы WAL, после пересоздания контейнера. Один контейнер обслуживает общую историю; схема рассчитана на один сервер с постоянным диском. Не удаляйте volume при обновлении. Кэш Next.js хранится в контейнере и при его пересоздании заполняется заново.

Просмотр логов:

```bash
docker logs --tail 100 -f kover-roller
```

Для обновления сначала соберите новый образ той же командой `docker build`, затем пересоздайте контейнер с прежним volume и `.env`:

```bash
docker stop kover-roller
docker rm kover-roller
docker run -d --name kover-roller --restart unless-stopped --env-file .env -e HISTORY_DB_PATH=/app/data/roll-history.sqlite -p 3000:3000 -v kover-roller-data:/app/data kover-roller:local
```

Для переноса существующей истории остановите приложение и перенесите весь каталог базы в volume. Альтернатива — bind mount существующего каталога вместо named volume: он должен быть доступен на запись пользователю контейнера. Без постоянного mount история исчезнет при удалении контейнера.

## Логирование

Сервер пишет JSON-записи в терминал: начало и завершение API-запросов, статус и длительность обращений к Nexusmods, ошибки и выбранный мод с числом попыток. Обновление списка игр и сохранение истории также записываются в лог. Запрос к приложению и вложенные обращения связаны полем `requestId`; тот же идентификатор возвращается в заголовке `x-request-id`. При сборке или фоновом обновлении кэша входящего запроса может не быть, поэтому такие записи не имеют `requestId`.

По умолчанию используется уровень `info`. В `.env` можно задать `LOG_LEVEL=debug`, `info`, `warn` или `error`. Уровень `debug` дополнительно показывает начало обращений к Nexusmods и причины пропуска модов. Изменение уровня применяется после перезапуска сервера.

`cachePolicy` показывает настройку кэширования обращения, а не подтверждённое попадание в кэш. Ключ API, заголовки авторизации, тела ответов и произвольные сообщения сетевых исключений не записываются. Отмена запроса имеет уровень `info`, ошибки запроса — `warn`, серверные сбои и таймауты — `error`. Логирование здесь охватывает серверную работу с Nexusmods; ошибки музыки и буфера обмена по-прежнему показываются в интерфейсе.

Автоматического сохранения в файл нет. Для сохранения вывода в PowerShell:

```powershell
New-Item -ItemType Directory -Force logs | Out-Null
bun run start 2>&1 | Tee-Object -FilePath logs/server.log -Append
```

Файл при этом пополняется без ротации; каталог `logs` исключён из Git.

## Общая история

Справа от рулетки на широком экране, а на узком — под ней, показываются последние 20 успешных выпадений для выбранной игры от всех посетителей, включая собственные. В записи есть название мода, ссылка на Nexusmods и время выпадения; имена пользователей, IP-адреса и идентификаторы посетителей не сохраняются. Повторное выпадение одного мода создаёт отдельную запись. Взрослый контент исключается из ленты, пока соответствующий переключатель выключен.

Лента обновляется после завершения собственной прокрутки, каждые 15 секунд на открытой вкладке и кнопкой «Обновить историю». При смене игры или фильтра старый запрос отменяется; во время прокрутки обновление приостанавливается.

История хранится в локальной SQLite через `@libsql/client`; облачный аккаунт или отдельный сервер базы данных не нужны. Файл по умолчанию — `data/roll-history.sqlite`, относительно каталога запуска приложения. База создаётся при первом обращении. Можно задать в `.env` другой путь, например:

```dotenv
HISTORY_DB_PATH=./data/roll-history.sqlite
```

Для сервера с постоянным диском укажите путь на этом диске. Не храните базу внутри `.next`: сборка приложения не должна удалять историю. Для переноса или резервной копии остановите приложение и скопируйте каталог базы целиком. В рабочем режиме SQLite может создавать файлы `-wal` и `-shm` рядом с основной базой. Каталог `data` исключён из Git; записи хранятся без автоматического удаления, хотя интерфейс показывает только последние 20.

Ролл теперь выполняется через `POST /api/getModInfo`, поскольку он сохраняет результат. Чтение истории — `GET /api/history?game=fallout4&boobs=false`. Если сохранение истории не удалось, найденный мод остаётся доступным, интерфейс показывает предупреждение, а сервер пишет `history.write_failed`. Сбой чтения отображается в ленте и записывается как `history.read_failed`.

## Использование

Выберите игру и нажмите кнопку "Роллим!".

Цифры прокручиваются минимум 5 секунд. Если поиск занимает больше времени, анимация продолжается до завершения запроса; результат появляется, когда закончились и поиск, и пятисекундное ожидание.

Вы можете скопировать ссылку на мод, нажав на кнопку "Скопировать ссылку на мод", чтобы позднее открыть его в браузере. Чтобы сразу открыть страницу мода, нажмите на кнопку "Открыть в новой вкладке".

Чтобы включить музыку, переключите переключатель "Музыка". Регулировать громкость можно с помощью ползунка.
